## What the inventory files mean

- config/inventory.schema.json: structural rules and allowed field types. It contains
  no account inventory. The CLI supports the explicit checked-in keyword subset;
  semantic checks add cross-reference and coverage validation.
- config/inventory.json: editable records and references to authoritative configuration.
  Its $schema association enables editor hints and structural validation.
- docs/INVENTORY.md: generated reading view of those records, links, skills, and helpers.
  Regenerate it with agents-config docs; CI rejects stale generated content.

Cloudflare zone.permissions is deprecated legacy membership data, not API-token grant
introspection ([official reference](https://developers.cloudflare.com/api/resources/zones/methods/get/)).
Read-only checks do not establish DNS Edit or other mutation permissions; those remain
declared grants until an authorized operation tests them.

A schema is not a secret scanner or an authentication check. Free-text notes still
require careful handling. CI secret scanning and explicit live reads are separate checks.

## Scope and recovery limits

The catalog covers declared/managed agent configuration, not every secret or application
on the computer. Provider checks apply to the explicitly selected manifest; success
for Paul/WebArts does not establish access to another account. Native OAuth/keychain
stores remain application-owned and are not read by inventory checks. GitHub CLI and
agent connectors can select different accounts.

Git restores context and configuration references, not credential values. Recovery
requires an encrypted secret backup, native sign-in, or provider replacement. Older
installer backups lack installed-content snapshots and retain their original link-only
check; preserve newer edits before restoring those. Full paid-resource bootstrap,
SMS delivery, and unrelated application behavior are outside this read-only review.
